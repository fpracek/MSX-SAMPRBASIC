# SamPr Basic on MSX — Z80 compiler (stages 1, 2a, 2b)

The BASIC compiler runs **on the MSX2** (MSX-DOS 1/2, no help from a PC). Full project and staged plan:
`../DESIGN-ONMSX.md`.

## Usage (on the machine)
Copy `dist\SAMPRBAS.COM` (editor), `dist\QBC.COM` (compiler) and `dist\RT.BIN` (runtime) to the disk, then `SAMPRBAS PROG.BAS`, **F5** (or the Run menu).
F5 saves the source and chain-loads `QBC.COM`, which generates `PROG.COM`, writes it to disk and launches it.
When the program ends it waits for a key and reloads the editor. If compilation fails, the editor reopens on the
source with the cursor on the error line and the message in the title (`Line 4: Syntax error`).
DOS 1 has no EXEC: the chain uses a 135-byte loader (`ldr.asm`) copied to C000h and the command line
at 0080h as a mailbox (`" NAME.BAS"`, on error `" NAME.BAS E<line> <code>"`).

## Files
- `qbc.asm` — compiler (about 10 KB; the runtime is NOT embedded but is read from `RT.BIN` when compilation starts): lexer, expressions, statements, direct emission of machine code.
- `rtcom.asm` — runtime for .COM (image at 0100h with a JP table, `rtabi.inc`), BIOS via CALSLT.
- `ldr.asm` — chain loader. Build: `ldr.asm` → `rtcom.asm` → `qbc.asm` (`--raw`/SAVEBIN in `build/`).
- `zrun.py` — quick test without an MSX emulator (Z80 emulator in Python + fake BDOS/BIOS, random RAM).
- `qtest.py` — real test on openMSX/MSX-DOS 1 (compiles and runs t1,t6,t7 from `../tests` + `qtests/`).
- `gtest.py` + `gtests/` — graphics test on openMSX (.bas programs and .chk pixel checks).
- `qtests/` — q1..q3 (block IF, loops, operators, hex/bin, LOCATE) and e1..e5 (error codes).
- Editor tests with F5: `../editor/erun.py`.

## Language (stages 1, 2a-2d, 3a-3b: graphics)
16-bit integers and strings (max 255). `PRINT` (`;` `,` `?`), assignments (`LET` optional), single-line `IF/THEN/ELSE`,
`IF/ELSEIF/ELSE/END IF`, `FOR/NEXT` (constant STEP, also negative), `WHILE/WEND`, `GOTO/GOSUB/RETURN`, `CLS`,
`LOCATE r,c`, `END`, `REM` and `'`, `INPUT ["text";|,] var` (integer or string), `DIM a(n), b$(m)` (arrays of integers and of
strings, indices 0..n, bounds checking), `POKE`.
Operators `+ - * / \ MOD AND OR XOR NOT = <> < > <= >=` (also between strings; `+` concatenates), constants `&H`/`&B`.
Functions: `LEN ASC VAL ABS SGN RND PEEK TIMER CHR$ STR$ LEFT$ RIGHT$ MID$ INKEY$`.
`SUB`/`FUNCTION` with by-value parameters (integers and strings), local variables, recursion, `CALL`, calling a SUB without
`CALL`, `DECLARE` (ignored: signatures are read with a pre-scan, so you can call before the definition),
`SHARED`, `EXIT SUB/FUNCTION`, FUNCTION result by assigning to its name (`f = ...`, `f$ = ...`).
`DO/LOOP` (`DO WHILE|UNTIL`, `LOOP WHILE|UNTIL`), `EXIT DO/FOR/WHILE`, `SELECT CASE` integer or string (`CASE 1`, `CASE 2, 3`,
`CASE 4 TO 6`, `CASE IS >= 7`, `CASE "a", "b" TO "m"`, `CASE IS < "a"`, `CASE ELSE`; the CASE values must have the
type of the selector). The string selector is copied onto the stack (256 bytes) for the whole block: recursion is safe.
IX frame: parameters on the stack (the first one deepest), heapp saved at (ix-2), 29 local integers, 256 bytes for
each local string; string temporaries are freed at the end of the statement down to the value saved on entry.
**Arrays as parameters**: in the signature `SUB f(a(), n)` / `FUNCTION g$(s$())`, in the call `f v(), 6` or `g$(w$())`;
the array is passed by reference (base and number of elements: two words on the stack), you can read and write `a(i)` with
bounds checking, you can pass it on to other routines, and `UBOUND(a)` gives the maximum index (also for global arrays).
The element type must match; an array parameter used without an index is a type error.
**MSX2 bitmap graphics** (`SCREEN 5` 256x212x16, `6` 512x212x4, `7` 512x212x16, `8` 256x212x256; the other modes 0-4 can
be selected but the graphics primitives give "Graphics needs SCREEN 5-8"): `SCREEN n`, `PSET (x,y)[,c]`, `PRESET (x,y)[,c]`
(background color), `POINT(x,y)` (-1 off screen), `LINE [(x1,y1)]-(x2,y2)[,c[,B|BF]]` (without the first point it starts from the last
graphics point; `B` box, `BF` filled box; omitted color = the one from `COLOR`), `CIRCLE (x,y),r[,c]`.
Off-screen coordinates are clipped (lines that leave the screen use point-by-point Bresenham), colors are the raw value of the
mode (0-15, 0-3, 0-255). The primitives use the VDP command engine (LINE, LMMV, PSET, POINT). Not yet: `PAINT`, text in graphics mode,
sprites, `PALETTE`. In graphics mode, at the end of the program it waits for a key without a message.
`CONST name = [-]number {, ...}` (usable in expressions and as a `DIM` size; assigning to it is an error),
`COLOR fg[, bg]`, `RANDOMIZE n`, `SLEEP frames`, `STOP`, `VPOKE addr, v` / `VPEEK(addr)` (VRAM 0-16383 via BIOS),
`OUT port, v` / `INP(port)`.
The BIOS (CALSLT) destroys IX: the runtime saves it around every BIOS call.
Strings: each variable is a fixed 256-byte buffer; temporaries live on a bump heap released at the end of the
statement (and after IF/WHILE conditions). Names `A$` and `A` are distinct; `A%` = `A`.
`OPTION NUMBERED` (lines ordered by number, numbers only), `OPTION LABELS` (labels only), `OPTION MIXED` (default).
Limits: 14 KB source (tables moved to 3800h), 16 KB program, 96 labels, 100 variables/arrays, 20 SUB/FUNCTION (max 8 parameters, 64 in total), 32 local names per function, about 590 lines in OPTION NUMBERED, 24 nested blocks, names significant to 12 characters, program data up to (0006h)-0C00h.

## Error codes (editor tail)
1 syntax · 2 nonexistent label/line · 3 not yet supported (strings, arrays, functions) · 4 illegal character
· 5 unclosed block · 6 ELSE/END IF/NEXT/WEND without a block · 7 duplicate · 8 too many variables/labels/blocks
· 9 program too large · 10 source too large · 11 read · 12 write · 13 not allowed with the chosen OPTION · 14 incompatible types or undeclared array · 15 program data too large · 16 RT.BIN not found · 17-20 inline assembler (see stage 23).

## Results
`zrun.py` 47/47 (also with random initial RAM), `qtest.py` 47/47 (openMSX), `gtest.py` 23/23 (graphics: pixels, palette and text read from the VRAM) (openMSX; INPUT with keys typed by the test),
`../editor/erun.py` 12/12, `ecom.py` 25/25.
Graphics for games (stage 14): `VBANK`, 17-bit `VPOKE`/`VPEEK`, `VFILL`, `VWRITE`, `VREAD$`, `BASE(n)`, `VDP(n)` / `VDP(n)=v`, `STICK`, `STRIG`, `COLOR=(n,r,g,b)`, `COLOR=RESTORE`, `COLOR SPRITE(n)=c`, `COLOR SPRITE$(n)=colors` (gtest 250 checks).
Stage 15: `PSET/LINE ...,op` (PSET PRESET AND OR XOR and T...), `COPY (..)-(..),page TO (..),page,op`, `SET PAGE vis,act` (SCREEN 5-8, also CLS/text/PAINT/GET/PUT on the active page), `SET SCROLL x,y`, `DATA`/`READ`/`RESTORE [label immediately before a DATA]`, SCREEN 3 (PSET/POINT/LINE/CIRCLE; not PAINT/GET/PUT/text), SCREEN 10-12 (MSX2+ only: CHGMOD 8 + R#25 YJK/YAE; tested on openMSX FS-A1ST with `GMACHINE=Panasonic_FS-A1ST python gtest.py`, `p*.bas` tests). The whole chain (compiler + gtest) also runs on the FS-A1ST (turbo R, DOS2).
Stage 16 (sound): `BEEP`, `SOUND reg,val`, `PLAY v1$[,v2$[,v3$]]` (blocking 3-voice MML: A-G # + -, R, O, L, T, V, N, < >, dots; tempo at 1-JIFFY resolution; tested with `stest.py`, which samples the PSG registers). Memory: runtime RAM at C090h, compiler tables at 3400h, source up to 15 KB.
Stage 17 (text files): `OPEN name$ FOR INPUT|OUTPUT|APPEND AS [#]n` (n = 1-3), `CLOSE [#n,...]`, `PRINT #n,` (also with `,` for zones), `WRITE #n,`, `INPUT #n, var,...`, `LINE INPUT [#n,] var$`, `EOF(n)`, `KILL`; open files are closed at the end of the program. FCB + 128-byte random records, CRLF lines and a final ^Z; tested on MSX2/DOS1 and on FS-A1ST/DOS2 (`qtests/f*.bas`). Sound is tested in every command (BEEP, V, L, M/S, dots, T).
Stage 18 (ROM cartridges, compiler `QBCR.COM` + runtime `RTROM.BIN`): `OPTION TARGET ROM16 | ROM32 | ASCII8 | ASCII16 | KONAMI | SCC` as the first line; QBC.COM recognizes it and hands over to QBCR.COM (same command line). The result is `NAME.ROM` (AB header, INIT that enables page 2 and initializes the bank registers; 16 KB file for ROM16, 32 KB or more for the others); at the end of the program, after a key, the machine reboots. Files (OPEN...) are not available in cartridges (error).
Multi-segment (ASCII8/ASCII16/KONAMI/SCC): `SEGMENT n` (n = previous + 1) moves the code to segment n (window at 8000h; 16 KB for ASCII16, 8 KB for the others; segment 0 is fixed at 4000h-7FFFh with the runtime). A SUB/FUNCTION in another segment is called as usual (or `CALL FAR name`): the compiler emits `ld a,k / call RT_FARCALL`, the routine switches bank with a software stack and restores the bank on return (arguments and result pass normally; passed strings are copied into the heap). Labels and DATA stay in their own segment (GOTO between segments = error). Data: `INCBIN "file"` puts the bytes in the current segment (usually a whole segment to itself), `SETBANK n` maps segment n into the data window (`DATAWIN` = A000h for 8 KB banks, 8000h for ASCII16, where it coincides with the code window), `VCOPY memory, vram, count` copies to the VRAM (also in .COM files). Test: `rtest.py` (compiles on openMSX/DOS and launches the ROMs with -cart) and `qtests/e30-e34`.
Stage 19 (RAM mapper, `.COM` and cartridges): `MAPPERSEGS` (16 KB segments, 0 if there is no mapper; detected with non-destructive alias probes), `MALLOC` / `MFREE seg` (with MSX-DOS 2 it uses the mapper support routines via EXTBIO, otherwise it takes segments from the top), `MGET(seg, offs)`, `MPUT seg, offs, v`, `MREAD seg, offs, address, count` (mapper -> memory), `MWRITE ...` (memory -> mapper), `VARPTR(var)` / `VARPTR(a(i))` to obtain addresses. In .COM files, page 2 (8000h-BFFFh) is accessed by changing port FEh with interrupts disabled and restoring the previous segment; in cartridges (where page 2 is ROM) RDSLT/WRSLT on the RAM slot are used. Memory addresses of blocks must not lie in 8000h-BFFFh. `OPTION NUMBERED` is not available in the cartridge compiler. Source up to about 13.75 KB. Test: `qtests/m1.bas` (also on FS-A1ST/DOS 2) and `rtests/r16-r17`.
Stage 20: `DIM x(n) MAPPER` (integer array in the RAM mapper, up to 32768 elements in 4 segments obtained with MALLOC; used only as `x(i)` for reading/assignment, `UBOUND` works, it cannot be passed as a parameter nor to GET/PUT/READ) and `BSAVE name$, start, length [, S]` / `BLOAD name$ [, S] [, offset]` in the MSX binary format (FEh, start, end, execution); with `S` the data goes from/to the VRAM (VBANK applies). .COM only (cartridges have no DOS).
The compiler no longer keeps the runtime in the buffer: NAME.COM = RT.BIN copied from disk + generated code, with the header fields (name, data size, DATA, target) patched afterwards; the program starts from disk. This way the space for the program stays at almost 16 KB no matter how much the runtime grows.
Stage 21 (random-access files, .COM only): `OPEN name$ AS #n LEN = k` (or `FOR RANDOM`; records of 1 to 128 bytes), `FIELD #n, w AS a$, ...` (up to 8 fields, global string variables), `LSET`, `RSET`, `PUT #n [, rec]`, `GET #n [, rec]` (records start at 1; without a number, the next one), `LOF(n)`, `MKI$(n)`, `CVI(s$)`. Fields work by copying: GET fills the variables, PUT copies them into the buffer, padding with spaces. Test `qtests/f5.bas`, `f6.bas` (DOS 1 and DOS 2). Source up to about 13.5 KB.
Stage 22 (instrumented debugger): `OPTION DEBUG` (anywhere before the code to be followed; the compiler automatically chooses the runtime with the debugger, `RTD.BIN` / `RTROMD.BIN`, which normal programs do not pay for). Before every statement the compiler emits `ld hl,<line> / call RT_DBG`; the program starts stopped on the first statement. TEXT 40x24 screen: current line, scalar global variables with their value (integers and strings, .COM only; `V` next page), list of breakpoints. Keys: SPACE (or S, ENTER) one statement, `R` runs to the next breakpoint, `B` number ENTER sets/clears a breakpoint (ENTER alone = current line, 0 = clears them all), `C` clears all breakpoints, `Q` ends the program, CTRL-STOP during execution re-enters the debugger. The program's screen is intact on return: the VDP registers (BIOS copies), 960 bytes of VRAM (name table) and 512 (ASCII 32-95 glyphs) are saved, after turning on text mode, so it also works in interlaced screens (6, 7); verified in SCREEN 5: VRAM and registers identical to a run without the debugger. The state (1.6 KB) is taken from the top of the heap on the first call. In cartridges (ASCII8 tried) the debugger runs from the fixed segment but does not show variables; it takes about 1.5 KB of segment 0. Test: `dtest.py` (.COM, `dtests/d*.bas` + `.keys`), `drtest.py` (cartridges, `dtests/r1.bas`). The compiler has its tables moved by 100h (source up to about 13.25 KB).
Stage 23 (inline Z80 assembler): a `__ASM` ... `__ENDASM` block (on their own lines, upper or lower case) contains documented Z80 instructions, written as in any assembler. When the compiler sees `__ASM` in the source, it loads the `QASM.OVL` overlay (at 8000h, output buffer still empty), which rewrites the blocks in place as `# elements` lines (one line per line, so line numbers stay those of the source); at that point the compiler's `#` statement emits the bytes. Syntax: comments with `;` (the apostrophe is used for `AF'` and for `'x'` characters), local labels `name:` (also `name EQU expr` / `name: EQU expr`), decimal numbers, `$1F`, `0x1F`, `1FH`, `%101`, `101B`, `'x'`, `$` (current address), expressions with `+` and `-`, directives `DB`/`DEFB` (also `"..."` strings), `DW`/`DEFW`, `DS`/`DEFS n[,fill]`. The whole documented Z80 set: LD in every form (also `(IX+d)`, `I`, `R`), ALU, INC/DEC, 16-bit ADD/ADC/SBC, JP/JR/DJNZ/CALL/RET/RST with conditions, PUSH/POP, EX, rotations and BIT/RES/SET (also indexed), IM, IN/OUT, block instructions LDIR... A name that is not a local label belongs to BASIC: `LD HL,(CONTA)`, `LD A,(FLAG)`, `LD HL,NAME$`, `LD DE,CONTA+2` give the address of the global BASIC variable (integer or string; not the locals of SUB/FUNCTION, but with `SHARED` yes), and `JP FINE`, `CALL FINE`, `JP NZ,FINE` jump to the BASIC label. `JR`/`DJNZ` only to local labels. The block may change all registers except IX (frame of the SUB/FUNCTION) and must leave the stack balanced; the debugger does not stop inside blocks. Errors in the editor: 17 syntax/operand, 18 value or jump out of range, 19 duplicate symbol or missing `__ENDASM`, 20 `QASM.OVL` not found. It also works in cartridges (QBCR). Test: `asmtest.py` (724 instructions compared byte by byte with sjasmplus on the Z80 emulator, plus tests with labels and errors), `qtests/asm1-asm3`, `rtests/r19`.
F5 speed (measured on openMSX with the NMS-8250 disk delays, DOS1; the time is almost all disk, compilation takes less than 0.3 s). Before: about 20 s from F5 to program start. Now: (1) the runtime size is a word in the RT.BIN header (`RT_SIZE`), so a single block is read instead of the whole file; (2) the runtime has a build stamp (`RT_STAMP`: date, time, normal/debug variant): if NAME.COM already exists with the same stamp the compiler rewrites only the code and the header, without deleting and recopying the 13.5 KB of runtime (the file may stay longer than necessary: the extra code is never executed); (3) the editor does not save if the text is unchanged and already on disk; (4) if the text is unchanged and the program has just been run (the program, at the end of execution, reopens the editor with the command line `NAME.BAS +`), F5 relaunches NAME.COM directly without recompiling. (5) the editor's save overwrites the existing file in place instead of deleting and recreating it (1.3 s instead of 3.1 s); if the new text is shorter than the file, a ^Z (1Ah) is written after the text and the rest of the file is an ignored remainder: the editor stops reading at ^Z (load_chunk) and QBC truncates the source at the first ^Z; if the file is longer than the text by more than 1 KB it is recreated anyway (so the file does not keep much leftover). Timings: first compilation ~10 s, after an edit ~5 s (save 1.3 s + QBC 2 s + load), re-run without changes ~2 s. Test: `editor/esave.py`, `qtests/z1.bas`.
Stage 24 (editor): colors for BASIC keywords (yellow on blue, the rest white) in the `SAMPRBAS.COM` editor, computed in idle time without slowing typing; the cursor is now an inverse glyph with software blinking. See `../editor/README.md`.
Stage 25 (MSX1, in progress): the runtime recognizes the machine (ROM byte 002Dh, `M2FLAG` in the runtime RAM): on MSX1 text is 40 columns (80 on MSX2), VRAM access does not write R#14 (the TMS9918 does not have it: number 14 would overwrite R#6), `SCREEN` accepts only 0-3 (otherwise "Illegal function call") and the debugger writes only R#0-R#7. Verified on openMSX with a real MSX1 (Sony HB-75P): all the cartridges in `rtests/` (text, subs/functions, ASCII8/ASCII16/KONAMI/SCC segments, inline assembler, PEEK/POKE/VPOKE) and the debugger give the same screen as on MSX2, except `r16`/`r17` (RAM mapper, which does not exist on MSX1). `python m1rom.py` repeats on MSX1 the cartridges already compiled by `rtest.py`. The editor (`SAMPRBAS.COM`) also works on MSX1 at 40 columns (80 on MSX2, automatic choice; see `../editor/README.md`, test `e40.py`; without keyword colors). The complete flow (40-column `.COM` editor, F5, compiler, program, return to the editor) is verified on openMSX with a real MSX1 and MSX-DOS 1.03: `Sony_HB-75P` + disk interface `Panasonic_FS-FD1A` (with the AVT_DPF-550 interface it starts in Disk BASIC; Mitsubishi_ML-30DC_ML-30FD and Microsol_CDX-2 also work); at startup the DOS asks "Enter new date:" (ENTER). Scripts: `avvia_hb75p.bat` (MSX1, 40 columns) and `avvia_nms8250.bat` (MSX2, 80 columns) in the project root, with the `disco_prova` disk. F5 ~11 s with the disk delays. Testing on a real machine is what matters. Graphics modes 5-12, palette, pages, VDP commands and mapper remain MSX2 only.
Floats are not yet supported (the 32-bit implementation exists in the git tag `float-archive`).
Not tested on a real MSX (physical disk, Nextor/DOS2).

Stage 26 (documentation and names): the editor is called `SAMPRBAS.COM`, the sources are `.SPB` (the compiler appends `.SPB` if the extension is missing). The PDF manual and online help are generated from `../doc` (`gen_help.py`, `gen_pdf.py`). `zrun.py` (the simulator without an emulator) has not been updated after the MSX1 changes and today reports 25 failures (phase 2 without a screen); the reference test is `qtest.py` on openMSX, which passes.

Stage 27 (debugger with variables, multi-file cartridges, project directory):
- Debugger (`rtdbg.asm`, `dbgq.inc`): with `OPTION DEBUG` the compiler puts after each SUB/FUNCTION a record `[prev][start line][end line][n][n x 16 bytes of LOCT]`
  (linked list, pointer after the globals table). The hook saves IX (frame): inside a routine the panel shows locals and parameters first (prefix `>`);
  the `E` command asks for a name (`Q`, `N$`, `V(2)`, `N$(1)`, `V` = number of elements) and looks it up among locals and globals. Test: `dtest.py d6` (`dtests/d6.*`).
- Multi-file segmented cartridges (`mtest.py`): `NAME000.SPB` (segment 0, with the OPTIONs) and `NAME001...`; `norm_seg` maps a segment other than 000 back to file 000 if it exists;
  pre-scan of all files (`mf_prescan`), compilation moving on to the next file at end of file (`mf_advance` + `seg_switch`), ROM `NAME.ROM`, errors on the
  right file, misplaced OPTION and SEGMENT = error 13. The ROM's FCB is saved in `FCBSV` while a source is being read and the DMA goes back to `OUT0`.
- MSX-DOS 2: the tools are opened from the `SPBHOME` directory (`open_tool`), work takes place in `SPBPROJ` (`cd_proj`); `rt_cdhome` in the runtime and `cd_home` before
  reloading the editor or `QBCR`. With DOS 1 nothing changes.
- The tables of the .COM compiler have moved by 100h (`LABT 3E00h`, `SRC 4E00h`): the maximum source is now about 12.5 KB (15 KB for cartridges).
- `zrun.py`: file opening now follows the contents of the FCB (like the real DOS).

Stage 28 (.BIN segments, single OPTION TARGET, BIN target):
- `NAMEnnn.BIN` next to the sources of a multi-file cartridge = an already compiled segment, inserted as is (`mf_loadbin`, `mf_have` tries .SPB then .BIN, `mfkind`/`mfbin`); if the last segment is a .BIN the epilogue is not emitted. When segment 0 is left, `jp RT_END` is emitted. Test: `mtest.py` case D.
- Values of `OPTION TARGET`: `DOS`/`COM` (default), `BIN`, `ROM_16`, `ROM_32`, `ROM_ASCII8`, `ROM_ASCII16`, `ROM_KONAMI`, `ROM_KONAMISCC` (= SCC) plus the old names. `chk_rom` in QBC.COM forwards to QBCR.COM (cartridges) or QBCB.COM (BIN).
- BIN target (`-DBINMODE`): runtime `RTBIN.BIN` (ORG 8400h, `RTRAM` at D000h, stack from F000h with the BASIC stack saved at F000h, no DOS: files = error, `rt_end` restores INITXT and does `ret`), compiler `QBCB.COM` (tables moved by 100h, `IMGBASE` 8400h, output `NAME.BIN` in BLOAD format with `bin_hdr`, message `bin_done`). It is loaded with `CLEAR 200,&H83FF` / `BLOAD"NAME.BIN",R`. Limits: no files, RAM mapper, debugger. Test: `btest.py` (compiles under DOS, then starts MSX-BASIC without DOS with the .BIN alone). Name aliases tested by `rtests/r21-r24`; `qtests/dos1`.
- Compiler tables for cartridges: `FARTABC 4100h` (moved by 100h).
