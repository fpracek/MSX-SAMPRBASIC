COM

REM
---

REM comment
' comment

Comment: the rest of the line is
ignored. The apostrophe can also be
placed after a statement, on the same
line.

Example:
  REM this is a comment
  PRINT "hello"   ' so is this
See also: PRINT
LABELS
------

name:
10 PRINT "x"

A program can use labels (name: alone
on a line or in front of a statement)
and/or line numbers. GOTO, GOSUB and
the RESTORE reset accept either. The
mode is chosen with OPTION: NUMBERED
(numbers only, sorted by number),
LABELS (labels only) or MIXED
(default, both). Label names follow
the same rules as variable names.
Several statements on the same line
are separated by colons.

Example:
  start:
    PRINT "a" : PRINT "b"
    GOTO done
    PRINT "never"
  done:
    PRINT "end"
See also: OPTION, GOTO, GOSUB
TYPES
-----

a   a$   a(10)   a$(10)

There are two types: signed 16-bit
integers (-32768 to 32767) and strings
(up to 255 characters). The name of a
string variable ends with $; A and A$
are distinct variables. The % suffix
is accepted and ignored (A% is A).
Names are not case sensitive; the
first 11 characters plus the suffix
are significant. Undeclared variables
are 0 or the empty string. Numeric
values: decimal, hexadecimal &H1F,
binary &B101. The "true" value of a
comparison is -1, "false" is 0.

Example:
  n = &HFF
  b = &B1010
  PRINT n; b
  PRINT 3 > 2; 3 < 2
See also: DIM, CONST, OPERATORS
OPERATORS
---------

+  -  *  /  \  MOD
=  <>  <  >  <=  >=
NOT  AND  OR  XOR

Arithmetic: + - * / and \ (integer
division, / between integers too) and
MOD (remainder). Comparisons: = <> < >
<= >= (also between strings, in
alphabetical order). Bitwise logical
operators on integers: NOT AND OR XOR.
+ concatenates strings. When in doubt
about precedence use parentheses:
arithmetic operators come first, then
comparisons, then logical ones.

Example:
  PRINT 7 \ 2; 7 MOD 2
  PRINT 5 AND 3; 5 OR 3; 5 XOR 3
  PRINT "ab" + "cd"; "a" < "b"
See also: TYPES
CONST
-----

CONST name = [-]number {, name =
    number}

Defines numeric constants. They can be
used in expressions and as the size in
DIM; assigning a value to a constant
is an error.

Example:
  CONST max = 5, base = 100
  DIM a(max)
  a(max) = base + 1
  PRINT a(5)
See also: DIM
LET
---

[LET] variable = expression
[LET] array(i) = expression

Assigns a value to a variable or to an
array element. The word LET is
optional. The type of the expression
must match that of the variable
(otherwise error 14: type mismatch).

Example:
  LET a = 5
  b$ = "hello"
  c = a * 2
  PRINT b$; c
See also: DIM
END
---

END
STOP

Ends the program. In a .COM program it
shows "Press any key.." and waits for
a key (then returns to the editor if
it was started from it, to the DOS
prompt if you ran NAME.COM yourself);
in a cartridge it waits for a key and
restarts the machine. At the end of
the source the program ends by itself.
In a program STOP is the same as END
(there is no interactive debugger: see
OPTION DEBUG). With a second word, END
also closes blocks: END IF, END SUB,
END FUNCTION, END SELECT.

Example:
  PRINT "start"
  END
  PRINT "never"
See also: DEBUG
DECLARE
-------

DECLARE SUB name(...)
DECLARE FUNCTION name(...)

Accepted for compatibility and
ignored: SUB and FUNCTION signatures
are read by a pre-scan of the source,
so a routine can be called before it
is defined.
See also: SUB, FUNCTION
IF
--

IF condition THEN statement [ELSE
    statement]
IF condition THEN
  ...
[ELSEIF condition THEN
  ...]
[ELSE
  ...]
END IF

Executes statements depending on a
condition (true if nonzero). Single-
line form: IF a > 3 THEN PRINT "yes"
ELSE PRINT "no". Block form: IF ...
THEN at the end of a line, any number
of ELSEIF, an optional ELSE and END
IF. Blocks can be nested.

Example:
  n = 5
  IF n > 9 THEN
    PRINT "big"
  ELSEIF n > 3 THEN
    PRINT "medium"
  ELSE
    PRINT "small"
  END IF
See also: SELECT CASE, OPERATORS
FOR
---

FOR variable = start TO end [STEP
    step]
  ...
NEXT [variable]

Counting loop. STEP is an integer
constant, possibly negative; if
omitted it is 1. The loop is not
executed if the initial value already
exceeds the final one. EXIT FOR leaves
the loop. Loops can be nested.

Example:
  FOR i = 1 TO 10 STEP 3
    PRINT i;
  NEXT i
  PRINT
  FOR j = 3 TO 1 STEP -1
    PRINT j;
  NEXT j
See also: EXIT
WHILE
-----

WHILE condition
  ...
WEND

Repeats the block as long as the
condition is true (tested at the
start). EXIT WHILE leaves the loop.

Example:
  n = 3
  WHILE n > 0
    PRINT n;
    n = n - 1
  WEND
See also: DO, EXIT
DO
--

DO [WHILE|UNTIL condition]
  ...
LOOP [WHILE|UNTIL condition]

Loop with the test at the start
(condition after DO) or at the end
(after LOOP), or without a condition
(infinite loop, to be left with EXIT
DO). UNTIL repeats until the condition
becomes true.

Example:
  n = 0
  DO
    n = n + 1
  LOOP UNTIL n >= 4
  PRINT n
See also: WHILE, EXIT
EXIT
----

EXIT FOR | EXIT WHILE | EXIT DO
EXIT SUB | EXIT FUNCTION

Immediately leaves the current loop
(FOR, WHILE, DO) or routine (SUB,
FUNCTION).

Example:
  FOR i = 1 TO 100
    IF i * i > 50 THEN EXIT FOR
  NEXT i
  PRINT i
See also: FOR, DO
SELECT CASE
-----------

SELECT CASE expression
  CASE value {, value | from TO to}
  CASE IS operator value
  CASE ELSE
END SELECT

Chooses among several alternatives
based on an integer or string value. A
CASE can list values (CASE 2, 3),
ranges (CASE 4 TO 6), comparisons
(CASE IS >= 7); with strings also CASE
"a", "b" TO "m". The type of the
values must match that of the
selector. CASE ELSE catches the rest.

Example:
  n = 5
  SELECT CASE n
    CASE 1, 2
      PRINT "few"
    CASE 3 TO 6
      PRINT "medium"
    CASE IS > 6
      PRINT "many"
    CASE ELSE
      PRINT "zero"
  END SELECT
See also: IF
GOTO
----

GOTO label | number

Jumps to the given label or line
number. In a multi-segment cartridge
the target must be in the same
segment.

Example:
  i = 0
  again:
    i = i + 1
    PRINT i;
    IF i < 3 THEN GOTO again
See also: GOSUB, LABELS
GOSUB
-----

GOSUB label | number
RETURN

GOSUB calls a subroutine that starts
at the label (or line number) and
RETURN goes back to the statement
after the call. For routines with
parameters and local variables use SUB
and FUNCTION.

Example:
  GOSUB greet
  PRINT "end"
  END
  greet:
    PRINT "hello"
    RETURN
See also: SUB, CALL
SUB
---

SUB name [(parameter {, parameter})]
  ...
END SUB

Defines a procedure. Parameters are
passed by value (integers or strings,
with $); an array is passed by
reference by writing a(). Variables
used inside the SUB are local, except
those declared with SHARED. It can be
called with CALL or directly by name.
Recursion is allowed. At most 20
routines, 8 parameters each.

Example:
  SUB addup(a, b)
    PRINT a + b
  END SUB
  CALL addup(3, 4)
  addup 5, 6
See also: FUNCTION, CALL, SHARED
FUNCTION
--------

FUNCTION name[$] [(parameters)]
  ...
  name = value
END FUNCTION

Like a SUB but returns a value: it is
assigned to the function name (name =
... or name$ = ... for strings). It is
used inside expressions. Recursion
allowed.

Example:
  FUNCTION twice(n)
    twice = n * 2
  END FUNCTION
  PRINT twice(21)
See also: SUB, CALL
CALL
----

CALL name [(arguments)]
CALL FAR name [(arguments)]

Calls a SUB. The parentheses are
optional. CALL FAR forces a call
between segments of a cartridge
(normally the compiler recognizes this
by itself). CALL calls a SUB, not a
label: for labels use GOSUB.

Example:
  SUB p(x$)
    PRINT x$
  END SUB
  CALL p("hello")
See also: SUB, SEGMENT
SHARED
------

SHARED variable {, variable}

Inside a SUB or FUNCTION, declares
that the given names are the global
variables (and not local variables
with the same name).

Example:
  total = 0
  SUB addto(n)
    SHARED total
    total = total + n
  END SUB
  addto 5
  addto 7
  PRINT total
See also: SUB, DIM
DIM
---

DIM name(n) [, name$(m) ...]
DIM name(n) MAPPER

Declares arrays of integers or strings
with indexes from 0 to n (so n+1
elements). Indexes are checked: out of
range the program stops with an error.
UBOUND(a) gives the last index. Arrays
are passed to SUB and FUNCTION by
writing a(). With MAPPER (only .COM
and cartridges with a RAM mapper) an
integer array lives in the RAM mapper,
up to 32768 elements.

Example:
  DIM a(4), n$(2)
  FOR i = 0 TO 4
    a(i) = i * i
  NEXT i
  n$(1) = "one"
  PRINT a(3); n$(1); UBOUND(a)
See also: UBOUND, MALLOC
UBOUND
------

UBOUND(array)

Returns the maximum index of an array
(even when it is a routine parameter).

Example:
  DIM v(9)
  PRINT UBOUND(v)
See also: DIM
DATA
----

DATA value {, value}
READ variable {, variable}
RESTORE [label]

DATA holds values (integers or strings
in quotes); READ reads them in order
into the given variables; RESTORE
moves reading back to the first DATA
or to the one immediately following
the given label. Reading past the last
DATA is an error.

Example:
  DATA 10, -20, "hello"
  READ a, b, s$
  PRINT a; b; s$
  RESTORE
  READ c
  PRINT c
See also: DIM
MKI$
----

MKI$(n)
CVI(string$)

MKI$ converts an integer into a 2-byte
string; CVI does the opposite. They
are used with random-access files
(FIELD fields).

Example:
  a$ = MKI$(1000)
  PRINT LEN(a$); CVI(a$)
See also: FIELD
PRINT
-----

PRINT [expression {; | , expression}]
    [;]
? expression
PRINT #n, ...

Writes to the screen. The semicolon
leaves the cursor right after the last
item; the comma advances to the next
tab zone (columns that are multiples
of 14). Without a trailing semicolon
it moves to a new line. Numbers are
preceded by a sign (a space if
positive) and followed by a space;
strings are written as they are. ? is
an abbreviation of PRINT. With #n, it
writes to the open file.

Example:
  PRINT "sum:"; 3 + 4
  PRINT 1, 2, 3
  PRINT "a";
  PRINT "b"
See also: LOCATE, INPUT, OPEN
INPUT
-----

INPUT ["text" ;|,] variable
INPUT #n, variable {, variable}

Reads a line from the keyboard into
the variable (integer or string). With
the text and the semicolon the text is
followed by "? "; with the comma it is
not. Confirm with Enter; Backspace
deletes. A non-numeric value in an
integer variable gives 0. With #n, it
reads from the file.

Example:
  INPUT "Name"; n$
  INPUT "Age", e
  PRINT "Hello "; n$; e + 1
See also: LINE INPUT, INKEY$
LINE INPUT
----------

LINE INPUT [#n,] variable$

Reads a whole line (spaces and commas
included) into a string variable; from
the keyboard or, with #n,, from a
file.

Example:
  LINE INPUT a$
  PRINT "[" ; a$ ; "]"
See also: INPUT
CLS
---

CLS

Clears the screen and moves the cursor
to the top left (on the active page in
SCREEN 5-8).

Example:
  CLS
  PRINT "clean"
See also: LOCATE
LOCATE
------

LOCATE row, column

Positions the text cursor. Row and
column start at 1.

Example:
  CLS
  LOCATE 5, 10
  PRINT "here"
See also: PRINT, CLS
COLOR
-----

COLOR foreground[, background[,
    border]]
COLOR = (n, r, g, b)
COLOR = RESTORE
COLOR SPRITE(n) = color
COLOR SPRITE$(n) = colors$

Sets the foreground, background and
border colors with numbers from 0 to
15 (in SCREEN 8 the raw value 0-255).
Without the third value the border
takes the background color. COLOR =
(n,r,g,b) redefines a palette color
(r, g, b from 0 to 7; MSX2) and COLOR
= RESTORE restores the default
palette. For COLOR SPRITE see sprites.

Example:
  COLOR 15, 4
  CLS
  PRINT "white on blue"
See also: PALETTE, SCREEN
INKEY$
------

INKEY$

Returns the character of the key
pressed, or the empty string if there
is none: it does not wait.

Example:
  DO
    k$ = INKEY$
  LOOP WHILE k$ = ""
  PRINT "key:"; ASC(k$)
See also: INPUT, STICK

LEN(string$)

Length of a string.

ASC(string$)

VAL(string$)

Numeric value of a string; stops at

STR$(number)

RIGHT$(string$, n)

MID$(string$, start [, n])

---

ABS(n)

Absolute value.

Example:
  PRINT ABS(-7)

SGN
---

SGN(n)

Sign: -1, 0 or 1.

Example:
  PRINT SGN(-9); SGN(0); SGN(4)

RND
---

RND(n)
RANDOMIZE seed

RND(n) returns a pseudo-random number
from 0 to n-1. RANDOMIZE sets the seed
of the sequence: the same seed gives
the same sequence.

Example:
  RANDOMIZE 7
  FOR i = 1 TO 5
    PRINT RND(100);
  NEXT i
See also: TIMER
TIMER
-----

TIMER

Video frame counter (1/50 or 1/60 of a
second) read from JIFFY; 16-bit, wraps
around to zero.

Example:
  t = TIMER
  SLEEP 25
  PRINT TIMER - t
See also: SLEEP
PEEK
----

PEEK(address)
POKE address, value

PEEK reads a byte of memory; POKE
writes it. 16-bit addresses (0 to
65535, also with equivalent negative
values).

Example:
  POKE 50000, 77
  PRINT PEEK(50000)
See also: VARPTR
POKE
----

POKE address, value

Writes a byte to memory. See PEEK.

Example:
  POKE 50000, 12
  PRINT PEEK(50000)
See also: PEEK
SLEEP
-----

SLEEP frames

Waits for the given number of video
frames (50 or 60 per second depending
on the machine's standard).

Example:
  PRINT "wait"
  SLEEP 50
  PRINT "done"
See also: TIMER
SCREEN
------

SCREEN mode [, sprite size]

Selects the video mode. MSX1: 0
(40-column text), 1 (32-column color
text), 2 (256x192 graphics), 3 (64x48
blocks). MSX2 adds 4, 5 (256x212, 16
colors), 6 (512x212, 4 colors), 7
(512x212, 16 colors), 8 (256x212, 256
colors) and, on MSX2+/turbo R, 10-12
(YJK colors). PSET, LINE, CIRCLE,
PAINT, GET/PUT and COPY work in SCREEN
5-8 (PSET, POINT, LINE and CIRCLE also
in SCREEN 3). The second parameter is
the sprite size: 0 = 8x8, 1 = 8x8
magnified, 2 = 16x16, 3 = 16x16
magnified. On MSX1 a mode above 3
gives "Illegal function call".

Example:
  SCREEN 5
  COLOR 15, 4
  CLS
  PSET (10, 10), 15
  LINE -(100, 80), 8

Available: MSX1: modes 0-3; MSX2: 0-8
(10-12 on MSX2+)
See also: PSET, LINE, SPRITE, SET
PSET
----

PSET (x, y) [, color [, operation]]
PRESET (x, y) [, color [, operation]]

Turns a point on (PSET) or off
(PRESET, background color). Off-screen
coordinates are clipped. The logical
operation is PSET, PRESET, AND, OR,
XOR or the same prefixed with T
(transparent: color 0 does not write).

Example:
  SCREEN 5
  PSET (128, 100), 12
  PSET (128, 100), 3, XOR

Available: MSX2 only (including SCREEN
3)
See also: POINT, LINE
POINT
-----

POINT(x, y)

Color of the point; -1 if off-screen.

Example:
  SCREEN 5
  PSET (5, 5), 9
  PRINT POINT(5, 5)

Available: MSX2 only
See also: PSET
LINE
----

LINE [(x1, y1)] - (x2, y2) [, color [,
    B|BF [, operation]]]

Draws a line; without the first point
it starts from the last graphics
point. With B it draws a rectangle,
with BF a filled rectangle. If the
color is omitted the COLOR value is
used. Not to be confused with LINE
INPUT (which reads a line of text).

Example:
  SCREEN 5
  LINE (10, 10)-(100, 60), 15
  LINE (20, 80)-(120, 140), 9, BF

Available: MSX2 only (including SCREEN
3)
See also: CIRCLE, PSET
CIRCLE
------

CIRCLE (x, y), radius [, color]

Draws a circle.

Example:
  SCREEN 5
  CIRCLE (128, 106), 50, 11

Available: MSX2 only (including SCREEN
3)
See also: LINE, PAINT
PAINT
-----

PAINT (x, y) [, color [, border]]

Fills an area starting from the given
point. In the 16-color and 4-color
modes the border (the color that stops
the fill) must be given if it differs
from the fill color.

Example:
  SCREEN 5
  CIRCLE (128, 106), 50, 4
  PAINT (128, 106), 6, 4

Available: MSX2 only
See also: CIRCLE, LINE
DRAW
----

DRAW "commands"

Draws with a command language: U D L R
E F G H (move up, down, left, right
and diagonally by n points), M x,y
(move to; +/- relative), B before a
command (move without drawing), N
(draw and return), C color, S scale
(in quarters). Example: DRAW "C7 R20
D10 L20 U10".

Example:
  SCREEN 5
  PSET (100, 100)
  DRAW "C8 R40 D30 L40 U30"

Available: MSX2 only
See also: LINE
GET
---

GET (x1,y1)-(x2,y2), array
PUT (x, y), array [, operation]

GET copies a screen rectangle into an
integer array; PUT redraws it with an
operation (PSET, PRESET, AND, OR,
XOR). In graphics the rectangle must
fit in an array dimensioned with DIM.
Not to be confused with GET #n / PUT
#n (random-access files) and PUT
SPRITE.

Example:
  SCREEN 5
  DIM a(100)
  CIRCLE (20, 20), 8, 15
  GET (10, 10)-(30, 30), a
  PUT (100, 100), a, PSET

Available: MSX2 only
See also: COPY, PUT SPRITE, OPEN
COPY
----

COPY (x1,y1)-(x2,y2)[,page] TO
    (x3,y3)[,page] [, operation]

Copies a screen rectangle (also
between pages) using the VDP command
engine: very fast, ideal for software
sprites and scrolling.

Example:
  SCREEN 5
  CIRCLE (30, 30), 20, 12
  COPY (0, 0)-(60, 60) TO (150, 100)

Available: MSX2 only
See also: GET, SET
SET
---

SET PAGE visible, active
SET SCROLL x, y

SET PAGE selects the displayed page
and the page being drawn on (SCREEN
5-8): draw off-screen and then show
it, for flicker-free animation. SET
SCROLL scrolls the screen smoothly
(registers 23 and 18).

Example:
  SCREEN 5
  SET PAGE 0, 1
  CIRCLE (100, 100), 40, 15
  SET PAGE 1, 1

Available: MSX2 only
See also: COPY, VBANK
VIEW
----

VIEW [(x1,y1)-(x2,y2)]
WINDOW [SCREEN] [(x1,y1)-(x2,y2)]

VIEW restricts drawing to a window of
the screen (without arguments it
cancels it); WINDOW redefines the
coordinate system (WINDOW SCREEN: the
y axis grows downward).

Example:
  SCREEN 5
  VIEW (50, 50)-(150, 150)
  LINE (0, 0)-(255, 211), 15
  VIEW

Available: MSX2 only
See also: LINE
PALETTE
-------

PALETTE n, r, g, b
PALETTE n, color
COLOR = (n, r, g, b)
COLOR = RESTORE

Redefines a palette color (r, g, b
from 0 to 7); the two-number form
assigns the given default color to
color n. COLOR = RESTORE restores the
factory palette.

Example:
  SCREEN 5
  PALETTE 1, 7, 0, 0

Available: MSX2 only
See also: COLOR

SPRITE
------

SPRITE$(n) = string$
PUT SPRITE plane, (x, y), color,
    pattern
PUT SPRITE plane
COLOR SPRITE(plane) = color
COLLISION

Sprites are 32 hardware objects.
SPRITE$(n) = string$ defines pattern
n: 8 bytes for an 8x8 (32 for a
16x16), one bit per dot. PUT SPRITE
plane,(x,y),color,pattern shows the
sprite; with just PUT SPRITE plane it
is hidden. The size (8x8 or 16x16,
normal or magnified) is chosen with
the second parameter of SCREEN. COLOR
SPRITE(n) = c changes the color of a
plane; COLOR SPRITE$(n) = string$
gives one color per line (MSX2, sprite
mode 2). COLLISION is -1 if two
sprites have touched.

Example:
  SCREEN 2, 0
  SPRITE$(0) = CHR$(255)+CHR$(129)+CHR
    $(129)+CHR$(129)+CHR$(129)+CHR$(12
    9)+CHR$(129)+CHR$(255)
  PUT SPRITE 0, (100, 90), 8, 0

Available: MSX1 and MSX2 (SCREEN 1-8)
See also: SCREEN, COLLISION, STICK

See also: SPRITE

----

Plays a melody on 1-3 voices using the

FIELD
-----

FIELD #n, width AS var$ {, width AS
    var$}
LSET var$ = text$
RSET var$ = text$

Random-access files: FIELD splits the
record into fields tied to string
variables (up to 8); LSET/RSET fill
the field aligning left or right
(padding with spaces); PUT #n,r writes
record r, GET #n,r reads it (records
start at 1). LOF(n) gives the number
of records.

Example:

  LSET n$ = "Mario"
  LSET c$ = "Rossi"
  PUT #1, 1
  GET #1, 1
  PRINT n$; c$
  CLOSE #1

Available: DOS programs only (.COM)
See also: OPEN, MKI$, LOF

-------

SEGMENT n

In a multi-bank cartridge, moves the

(previous + 1). Segment 0 contains the

    PRINT "in segment 1"
  END SUB

Available: ASCII8/ASCII16/Konami/SCC
cartridges

OPTION TARGET
-------------

OPTION TARGET DOS | BIN
OPTION TARGET ROM_16 | ROM_32 |
    ROM_ASCII8 | ROM_ASCII16 |
    ROM_KONAMI | ROM_KONAMISCC

When it is the first line, it selects
what the compiler produces. DOS
(default, also COM): NAME.COM program
for MSX-DOS. BIN: NAME.BIN program for
MSX-BASIC, without DOS (see BIN).
ROM_16 and ROM_32: plain 16 or 32 KB
cartridge. ROM_ASCII8, ROM_ASCII16,
ROM_KONAMI and ROM_KONAMISCC (also
ROM_SCC): banked cartridges, with
segments (see SEGMENT and SEGMENTS).
The old names ROM16, ROM32, ASCII8,
ASCII16, KONAMI, SCC remain valid. A
cartridge waits for a key at the end
and restarts the machine; cartridges
have no files, no BLOAD/BSAVE and no
full debugger; the inline assembler
works.

Example:
  OPTION TARGET ROM_16
  PRINT "I am a cartridge"
See also: BIN, DOS, SEGMENT, OPTION
BIN
---

OPTION TARGET BIN

Produces NAME.BIN, a machine-language
program for MSX-BASIC, without MSX-
DOS. The file is in BLOAD format and
starts at address 8400h. From MSX-
BASIC: CLEAR 200,&H83FF and then BLOAD
"NAME.BIN",R. At the end of the
program it waits for a key and returns
to the BASIC prompt. Disk files (OPEN,
BLOAD, BSAVE...), the RAM mapper and
the debugger are not available;
everything else (graphics, sprites,
sound, strings, arrays, SUB/FUNCTION,
inline assembler) works as in DOS
programs. The code can reach about 12
KB beyond the runtime; data and heap
sit from D000h upward.

Example:
  OPTION TARGET BIN
  PRINT "Hello from MSX-BASIC"

Available: MSX1 and MSX2, no DOS
See also: DOS, OPTION TARGET, ASM
DOS
---

OPTION TARGET DOS

Default value: produces NAME.COM for
MSX-DOS (1 or 2) with access to disk
files. Equivalent to writing no OPTION
TARGET. DOS programs start at 0100h.
See also: BIN, OPTION TARGET

ASM
---

__ASM
  Z80 instructions
__ENDASM

An __ASM ... __ENDASM block (each on
its own line, upper or lower case)
contains documented Z80 code, written
as in any assembler. Comments with ;.
Local labels name: (also name EQU
value). Numbers: decimal, $1F, 0x1F,
1FH, %101, 101B, 'x'; $ is the current
address. Directives: DB/DEFB (also
strings), DW/DEFW, DS/DEFS. A name
that is not a local label is a global
BASIC variable (LD HL,(COUNT), LD
HL,NOME$) or, in a jump, a BASIC label
(JP DONE, JP NZ,DONE). JR and DJNZ
only to local labels. Every register
can be changed except IX (frame of
SUB/FUNCTION) and the stack must be
left balanced. The debugger does not
stop inside the blocks. It also works
in cartridges. OPTION ASM as the first
line makes the WHOLE file assembly (an
assembler editor): the block ends at
the end of the file, or at an optional
__ENDASM; there are no BASIC variables
or labels, the program starts at the
first line and ends when the code runs
off the end (or with JP/RET tricks of
your own); DOS programs only, not
cartridges. Errors: 17 syntax/operand,
18 value or jump out of range, 19
duplicate symbol or missing __ENDASM,
20 QASM.OVL not found.

Example:
  count = 0
  __ASM
    ld hl,(count)
    inc hl
    ld (count),hl
  __ENDASM
  PRINT count
See also: VARPTR, OPTION
DEBUG
-----

OPTION DEBUG

Write OPTION DEBUG in the source and
press F5: the program starts stopped
at the first statement, in a text
screen showing the current line, the
global scalar variables with their
value and the list of breakpoints.
Keys: SPACE (or S, ENTER) runs one
statement; R runs to the next
breakpoint; B number ENTER sets or
clears a breakpoint (ENTER alone =
current line, 0 = clear them all); C
clears all breakpoints; V next page of
variables; E asks for a variable name
(local, parameter, global, array
element such as V(3) or N$) and shows
its value; Q ends the program. Inside
a SUB the local variables and
parameters appear first with the >
prefix. CTRL-STOP while running re-
enters the debugger. The program
screen stays intact. In cartridges the
debugger works but does not show
variables. Normal programs (without
OPTION DEBUG) pay nothing.

Example:
  OPTION DEBUG
  s = 0
  FOR i = 1 TO 3
    s = s + i
  NEXT i
  PRINT s
See also: OPTION DEBUG
EDITOR
------

Esc = menu, arrows, F1-F4

Start it with SAMPRBAS name (also with
a path, on MSX-DOS 2). Keyboard menu:
Esc opens the File menu; F1 File, F2
Edit, F3 Find, F4 Help; Run is on the
right; left/right arrows change menu,
up/down the items, Enter selects, a
highlighted letter activates the item,
Esc closes. Shortcuts: F5 compiles and
runs, F6 Help on the word under the
cursor, F7 help index, F8 File >
Segment (changes segment). Keywords
are colored (on MSX2); on MSX1 the
editor has 40 columns, on MSX2 80,
automatically. If nothing has changed
F5 reruns the program immediately.
See also: HELP
SEGMENTS
--------

NAME000.SPB, NAME001.SPB ...
File > Segment... (F8)

A segmented cartridge (ASCII8,
ASCII16, KONAMI, SCC) is written as
one file per segment: NAME000.SPB
(segment 0, fixed, with the OPTIONs)
and NAME001, NAME002... (5 characters
+ 3 digits). The compiler reads them
in sequence and links them into
NAME.ROM; you compile from any file
with F5. The OPTIONs go only in file
000; SEGMENT is not written. A file
NAMEnnn.BIN (assembler, sprites, font,
data) is an already compiled segment:
it is inserted as is. F8 (File >
Segment...) saves the current file and
opens the segment whose number you
type (also without zeros); if the file
does not exist, or is a .BIN, it says
why and the active file does not
change. Numbering starts at 0: it is
the first block of the cartridge, not
the BIOS.
See also: SEGMENT, OPTION TARGET,
EDITOR
DIRECTORY
---------

SAMPRBAS \DIR\NAME
SET SPBHOME=\TOOLS

With MSX-DOS 2 the working directory
is always that of the open file:
source, .COM/.ROM and the program's
files live in the project folder, the
tools in theirs. You can give a path
on the command line; File > Open
navigates between folders. Environment
variables: SPBHOME (tools, the folder
the editor is first started from) and
SPBPROJ (project). With MSX-DOS 1
there are no folders.
See also: SPB, EDITOR
